# Chrome extension

Build from the repository root with `npm run build --workspace @oit/extension`. In Chrome, open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select `apps/extension/dist`.

Start the local API and document reader using the root setup instructions. A right-side control appears automatically on HTTP and HTTPS pages where Chrome permits this extension. Choose **Translate** to use your saved language and backend settings, then **Restore** to remove the translations. The control stays available for another translation; the original text, links and event handlers remain in place. The toolbar popup also provides language selection and translation controls.

The extension requests `activeTab`, `scripting` and `storage`, plus HTTP access to `localhost`/`127.0.0.1` for your local API. Declarative content scripts request access to HTTP and HTTPS websites so the page control can appear before opening the toolbar. Chrome's site-access setting must permit the page. Injection is limited to the top frame; the toolbar can additionally translate frames covered by its active-tab grant. A page control uses its own sender tab and previously injected frames. It cannot select another tab or supply backend credentials. Provider keys belong on the API server. Settings can change local API/reader ports, source/target language and bilingual theme.

The launcher is passive: installing it does not scan page paragraphs, start a translation job, or send page text to the backend. Translation begins after you choose Translate. After rebuilding an unpacked extension, use **Reload** on its card at `chrome://extensions`, accept any updated site-access permission, and reload website tabs. Repository builds cannot reload a user's installed extension automatically.

Paragraphs near the viewport are queued in bounded batches. When nearby content is finished, the control shows **Ready** with **Scroll to translate more** and stops spinning. Scrolling to deferred content resumes translation automatically; **Translated** means no paragraphs remain. The popup distinguishes active requests from deferred content too. Newly inserted or edited content is reconsidered after a short quiet period. Rich inline tags use a restricted identity-token grammar; code, equations and images remain local protected elements. Provider HTML is never inserted as HTML. Failures are summarized in the page control and popup, leaving source text and layout intact. Translate checks the service before scanning; a connection failure during translation pauses further requests until you choose Retry. The popup checks for reconnection automatically and disables Translate while the service is offline or needs a provider.

Translation uses server jobs and short polling requests. Slow local-model inference does not hold a Manifest V3 service worker fetch open. Restoring/restarting the page aborts polling and cancels the current server job; a session generation also prevents late results from entering the DOM.

This release supports bilingual mode only. Chrome internal pages, the Web Store, built-in PDF views, shadow-root contents and frames without active-tab permission are outside this DOM translator. Reloading or navigating clears translation and requires another user action. It does not translate image-only/canvas text. For PDFs and other files, use the document app. For the production server (`npm start`), change **Settings → Document app** to `http://127.0.0.1:8787`.

Tests cover paragraph grouping, exclusions, safe rich rendering, marker validation, restoration, stale pending responses, host edits and dynamic insertion without self-triggered translation loops.
