# Initial verification

Version: 0.1.0. Local checks performed during implementation:

- TypeScript strict checking and production reader/extension builds passed.
- 94 unit/integration tests passed: inline protection, original DOM identity/restoration, dynamic changes, source-version guards, short-job transport/cancellation, provider HTTP contracts, cache identity, queued cancellation, document import/edit/persistence, partial export policy, protected agent batch saves, constrained agent file/API operations, and Codex subprocess isolation, validation, cancellation, limits and redacted errors.
- 14 Chromium browser tests passed: document import/translation/edit/reload/HTML export, responsive controls, the built website content script connected to the API with original restoration, interface language persistence and edit preservation, localized Google/Codex setup, agent requests and clipboard fallback in the reader/extension, and exact document/language links for agent results.
- The official MCP client connected over stdio through the actual launcher from another working directory, discovered all eight tools, supplied translations with a provider unconfigured, and verified protected content, unique exports and download links. A separate live local example used translations authored by the calling agent to produce Chinese bilingual HTML and Markdown; no separate provider request or model download was made.
- The website browser test emulates Chrome's message transport. It executes the actual built content script, DOM observers and backend; it is not a complete native Chrome toolbar/permission installation test.
- On 2026-10-21, the installed Codex CLI and existing ChatGPT sign-in completed real `gpt-6.1-sol` requests through the production backend. A small public TXT document translated into Chinese, retained `$E=mc^2$` and `x = 1`, and exported as HTML/Markdown. The production website engine and short-job transport used the same backend in an isolated DOM test: a public paragraph translated into Chinese while its link and code survived, and Restore retained the original nodes. The built reader displayed the saved result in Chrome. No API key or local model download was used. Native extension loading still needs a manual Chrome step because the automation browser's URL policy blocks `chrome://extensions`.
- A local text-extraction check of the supplied 15-page scientific PDF produced 63 blocks and 51,337 characters. This verifies basic extraction, not reading-order accuracy, formula recovery or OCR.
- Desktop and mobile layouts were visually inspected. The README screenshot shows the actual built app.

Deterministic providers are explicitly selected for automated tests. Ollama/compatible wire formats are tested against local HTTP fixtures, and the Google Cloud Translation contract is tested with intercepted fetch responses. No live Google credentials or running local model were available for translation-quality assessment. The smaller Ollama default is a configuration choice, not a measured hardware or quality claim. The optional Docling model pipeline was not installed/executed in these lightweight checks.

Known dependency-audit result at creation: three moderate advisories follow Mammoth's CLI-only `argparse` → `sprintf-js` dependency chain. This application calls Mammoth's text-extraction library and does not run its CLI. No patched upstream version was available from the registry at inspection. Track upstream rather than downgrading the parser to an obsolete version. The current PDF.js dependency is beyond the reported vulnerable range.

Run the commands in the main README to reproduce checks. Job metadata is session-local; parsed documents, translations and cache persist across backend restarts. Complex PDF layout, DOCX formatting/images and shadow-root website content remain outside the initial fidelity scope.
